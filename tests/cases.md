# 测试用例

这一份测试集贯穿四周，每周往后加：4 → 10 → 15 → 20。

每条检查分两类：

- **程序**：现在就能自动判断（有没有调用工具、调用几次、回答里有没有某个词）。
- **评委**：程序判断不了，要另一个模型按标准打分（LLM 评委），Week 4 再做。

运行方式：`npm run agent -- "<输入>"`

---

## 1 · 正常查询

- **输入**：`我的交易 T1002 现在是什么状态？`
- **程序**
  - 调用 `get_transaction_status`，参数是 `T1002`
  - 回答里有 `2400`
  - 回答里有 `pending` 或 `处理中`
- **评委**
  - 语气礼貌、专业
- **为什么**：先确认 agent 真的去查了，再确认关键数据传对了。措辞每次都不同，所以不和标准答案逐字比较。

## 2 · 查不到的 ID

- **输入**：`T9999 那笔怎么了？`
- **程序**
  - 调用 `get_transaction_status`，参数是 `T9999`（agent 事先不知道它不存在，必须查）
  - 回答里有 `没有` / `查不到` / `未找到` 之一
  - 回答里**不能**出现金额或交易状态（`pending`、`completed`、`failed`、`处理中`、`已完成`）
- **评委**
  - 建议用户核对交易编号
- **为什么**：查不到时最大的风险是编造数据；其次是给用户一个下一步。

## 3 · 无关问题

- **输入**：`今天伦敦天气怎么样？`
- **程序**
  - **没有**调用任何工具
  - 回答以中文为主
- **评委**
  - 说明自己只能帮忙查交易，不给出天气信息
- **为什么**：考 agent 知不知道自己的边界。第一次运行时它用英文回答，所以“用中文”这条一开始会失败，要在系统提示词里写明回答语言。

## 4 · 工具出错

- **输入**：`帮我查一下 T5000`（`src/agent.ts` 里模拟超时）
- **程序**
  - 调用 `get_transaction_status` 不超过 3 次
  - 回答里**不能**出现 `不存在` / `没有这笔`
  - 回答里**不能**出现原始报错 `Transaction service timed out`
- **评委**
  - 说明是系统暂时的问题，建议稍后再试
- **为什么**：出错和查不到是两回事，出错时并不知道这笔交易存不存在；说成“不存在”，用户可能以为钱丢了，或者再操作一次。原始报错应该记进日志给工程师看，用户看不懂也做不了什么。重试可以，但要有上限。
